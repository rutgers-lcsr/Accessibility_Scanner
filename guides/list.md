## What this means

Something other than an `<li>` sits directly inside a `<ul>` or `<ol>`: a `<div>`, an `<a>`, a `<span>`, or loose text. Screen readers announce lists ("list, 5 items") and let people move item by item; a list with foreign children is announced wrongly or not as a list at all.

Menus and widgets generated by plugins are the usual source, and lists pasted from Word.

## Why it matters

"List of 5 items" tells a visitor how much is coming and lets them skip it. A broken list loses that and can hide items entirely. WCAG 1.3.1 (Info and Relationships).

## Before

```html
<ul class="menu">
  <a href="/">Home</a>
  <a href="/schedule">Schedule</a>
  <div class="item"><a href="/people">People</a></div>
</ul>
```

## After

```html
<ul class="menu">
  <li><a href="/">Home</a></li>
  <li><a href="/schedule">Schedule</a></li>
  <li><a href="/people">People</a></li>
</ul>
```

Only `<li>`, `<script>` and `<template>` may be direct children of a list. Styling wrappers go inside the `<li>`, not around it.

## WordPress

- Look at the selector on the report page: a menu or widget plugin's class means the plugin prints the bad markup. Update it, look for a "markup" or "accessibility" option, or replace it; the core **Navigation** block and `wp_nav_menu()` print correct lists.
- A **Custom HTML** block or a classic-editor page: edit the HTML so each item is an `<li>`.
- Content pasted from Word: select the list in the block editor and re-apply the **List** block, which rebuilds it.

## Canvas

Lists pasted from Word or Google Docs often arrive as paragraphs with bullet characters, or as a list with stray elements inside. Select the text, remove the list formatting and apply it again with the editor's **bulleted list** or **numbered list** button. In the HTML view, make sure every line inside `<ul>` is an `<li>`. The editor's **Accessibility Checker** flags some of these.

## GitHub Pages

Markdown lists always compile correctly. The failing list is in HTML you wrote in the markdown or in a theme include (a navigation include is the common one). Copy the include into your repository and give every item its own `<li>`.

## Plain HTML

Open the list the report names and make each entry an `<li>`, moving any wrapper `div` or `span` inside the item. Fix the template or include when the list is a menu that appears on every page.

## Check your fix

Use the **Rescan this page** action next to any affected page once your change is live. A menu fix clears every page; content lists clear page by page.
